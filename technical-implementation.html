Architecture and prototype delivery for the final web-based coursework scope

System Architecture

A full-stack prototype architecture supports a clear, testable coursework system

The final system combines a Vue frontend, Spring Boot backend, JWT authentication, cloud deployment, and a portfolio layer that explains how the prototype was designed, tested, and evaluated.

Content Layer

Case-study sections, evidence summaries, and future asset slots.

Presentation Layer

Responsive CSS system using reusable cards, grids, and section styles.

Asset Layer

Journey maps, persona boards, sketch boards, prototype exports, and contribution evidence.

Data Handling

User input and interaction states are translated into progress evidence

Input Capture

The student-side interface collects profile choices, planning-stage selections, task clicks, reward actions, and progress updates. These inputs drive personalised stage guidance, quest status, and feedback messages.

Interaction State

User progress is represented through visible states such as unlocked map nodes, completed quests, earned XP or coins, material crafting progress, and deadline-related task status.

Advisor View

The teacher-side dashboard summarises student progress, engagement, and reward redemption status so advisors can identify students who may need timely support.

  • index.html holds the complete single-page portfolio structure.
  • style.css defines the visual system, component styling, and responsive layout.

AI-assisted development process

Atomic Vibe Coding Loop

We used AI as a coding assistant, but each output was controlled through structured prompting, human review, testing, UX evaluation and version tracking.

Our vibe coding process followed an atomic loop: one user story, one component, one review cycle.

User Story Driven Human-in-the-loop Test-oriented Traceable Prompts

  1. For each node, such as the Y2-3 school matching task, our prompt included the target user background, the learning goal, the game mechanism, technical constraints, state management, accessibility requirements and testing expectations.

  2. We checked state logic, edge cases, empty data handling, interaction flow and whether the implementation matched our UX design. We paid special attention to parts that looked runnable but were not rigorous enough.

  3. Before implementation, we defined behaviours such as whether drag-and-drop ordering updated correctly, whether wrong actions triggered feedback and whether keyboard users could complete the task. AI helped draft tests, but we judged whether the tests were meaningful and added missing edge cases.

  4. We checked UI consistency, game-like animation, bilingual content, visual hierarchy and whether the interaction felt smooth. Screenshots and issue descriptions were used as feedback for further AI-assisted refinement.

  5. We reviewed whether the feature increased cognitive load, whether feedback was clear, whether users could make mistakes easily and whether the interaction matched users' intuition. This step reflected our human design judgement.

  6. We used Git and Notion to document prompt versions, AI-generated issues, our modification decisions and the related user requirements. The repository became a collaboration log between human designers and AI tools.

What Worked

LLMs accelerated layout, copy, and boilerplate implementation

Using Cursor and ChatGPT significantly accelerated frontend layout generation, Tailwind CSS iteration, and bilingual UI copy refinement. This saved boilerplate coding time and allowed the team to spend more effort on human-centred design decisions, evidence alignment, and interaction evaluation.

What Did Not Work

State logic, accessibility edge cases, and testing still required human control

AI struggled with rigorous state logic, such as cross-component reactivity in Vue 3 for the RPG progression system, and with complex accessibility edge cases. These areas required manual architectural decisions, human debugging, and review before integration.

Process evidence

AI-assisted process evidence

We treated AI outputs as reviewable engineering artefacts: prompts were versioned, generated solutions were checked by humans, backend and frontend tests were rerun, and Git history was used to track integration.
